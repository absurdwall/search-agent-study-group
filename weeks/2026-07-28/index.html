Week 3

Modern agent systems

A durable systems map and an Orders Agent workshop

July 28, 2026

In Weeks 1 and 2, we built an ADK agent, gave it tools, and inspected what happened during a run. This week, we step back and connect that experience to the larger systems that make an agent useful in real work, then use an Orders Agent workshop to inspect those ideas in concrete Phoenix traces.

Our learning path

We will move from the core runtime behavior to the layers that extend it. These ideas appear across agent products, even when the names and loading rules differ.

  1. Agentic loopHow an agent gathers context, acts, observes the result, and continues.
  2. ToolsHow the model gains actions beyond producing text.
  3. Context, instructions, and memoryWhat the agent can see now, what guidance persists, and what state is retained.
  4. MCPA standard way to connect an agent host to external tools, resources, and prompts.
  5. SkillsReusable instructions, workflows, scripts, and references loaded when relevant.

Workshop goals

  1. Register normal Python functions as agent tools.
  2. Use one tool to list orders, then two tools to inspect the latest order.
  3. Read Phoenix traces for model calls, tool calls, arguments, and token totals.

The workshop begins with a small simulated weather tool before moving to the Orders Agent. It uses synthetic classroom data, so learners can inspect the traces safely. It complements the durable book chapters; it does not add a new learner release to the Search Agent Lab repository.

Introduced briefly, expanded later

We will locate subagents, permissions, guardrails, and hooks on the map, but we will not try to master them this week. They become easier to reason about after the loop, context, and capability layers are clear.
